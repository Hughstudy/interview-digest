## 分章详解

### 第一章：开场——榜单满分与体感的落差（00:00 - 01:18）
泓君抛出全期的核心张力：每次新模型发布，各榜单成绩都在刷新，很多通用评测已接近满分，但这种进步"很多时候并没有变成工作中的进步"。电商是检验这一落差的好样本——从产品创意到卖向全球，中间隔着市场调研、找工厂、比报价、安排物流、多平台开店、核算利润一整条链，AI 到底能接手多少、会在哪一步卡住？半年前（今年3月）张阔首上节目聊刚发布的 Accio Work（当时他判断 Claude Cowork 比爆火的 OpenClaw 更值得关注，如今被市场印证），这次回访带着新证据：团队从实际业务里整理出 107 个任务，专门测试 AI 在无人干预的情况下能否把工作做完。这个开场为全期定了调——不聊愿景，聊"体感基准"与通用榜单的差距。

### 第二章：Coding 渗透率 99%，办公 Agent 为什么远落后（01:18 - 04:00）
张阔给出一个自报估计：Coding 的 Agent 渗透率约 99%——"很难看到身边有一个研发人员不用任何 AI 去写代码"，"现在绝大多数代码应该都是 AI 产生的"。而第二个垂直赛道的渗透率"可能都远远小于这个数字"。为什么顺序是这样？他给出两个结构性原因：其一，Coding 工作 100% 数字化，代码都在 GitHub 或 codebase 里，容易被 AI 广泛学习；其二，Coding 天然可验证（verifiable）——能不能编译、结果对不对，机器自己就能判断，这正好契合当前大语言模型的强化学习范式。反观商业场景：数据形态多元、没有通用流程可言、结果好坏的定义因企业而异（同样一单成交，是为利润还是为市场份额？），且反馈闭环以天、周、月甚至年计——不像编译错误那样即时。这个对比是全期论证的地基：**可验证性决定了 Agent 落地的顺序**，后面 107 任务基准正是把"不可验证"变成"可验证"的尝试。

### 第三章：Accio 的三阶段演进（04:00 - 06:12）
产品能力的三个阶段，也是 Agent 边界外扩的轨迹。阶段一是 AI 搜索（相当于 Alibaba.com 的 AI mode）：买家用自然语言或多模态方式描述需求，替代关键词查询。自报数据：整体搜索量 +20%，多模态搜索 +130%——说明用户表达需求的方式正在迁移。阶段二是 sourcing（采购）前后延展：从"搜一下"变成市场调研→产品 design pack（设计文档）设计→交给供应商推进沟通→完成交易，张阔称之为 agentic trade（AI 驱动的交易）。阶段三是今年 4 月推出的 Accio Work：不只管采购，而是帮用户一站式管理所有电商后台——理解多平台经营情况、管理供应链、管理企业和员工的日常经营表现。底层逻辑是阿里两大供应链平台（国内 1688 + 跨境 Alibaba.com）的 20 多年积累，用户天然是"在 1688 进货、在淘宝/抖音卖，或在 Alibaba.com 进货、在 Amazon/Shopify/eBay 卖"的电商人群。

### 第四章：案例：一个想法如何变成跨平台生意（06:12 - 10:20）
具体案例 Edward（CoCreate 大会讲过）：他喜欢种植物但经常把花养死，于是想做一个"让植物告诉你自己状态"的消费电子产品。真正的难点不在想法，而在从想法到可制造的产品：用什么检测设备、什么读取设备、怎么把成本压到零售时有毛利——这一步"可能难住很多的创业者"。Accio Work 的解法链条：先做 design pack 设计→匹配广州/深圳做电子产品最强的厂商→解决跨境问题（订船期、HS code 海关编码、物流管理）→生成社媒内容→上 Amazon/eBay/Shopify/TikTok 销售→跨平台管理店铺、内容合规、定价、买家反馈迭代。最有信息量的是人肉对照：没有 Agent 时，选供应商要维护一张约 20 列的 Excel（生产制造能力、资质、工厂水平、价格、账期、物流方案），在十几家供应商之间反复沟通，周期以月计才能拿到样品；有 Agent 后想法被分解成"可制造的产品+所需能力"，自动匹配商家并用商家的企业知识库内容推进沟通，24 小时内给出原来一个月才能维护出来的报表。供应商的反馈是"没见过这么专业的 design pack"——平时买家都是笔在纸上画一画就开始交流，导致大量纠纷和反复。需要留意：选择哪几家合作仍是人做的决定，这是人和 Agent 的协作点。（这章产品 demo 属性最强，数字全部自报。）

### 第五章：中美市场差异与 SaaS 生死（10:20 - 16:05）
办公场景的中美差异相对小，但企业软件生态的惯性不同：美国 SaaS 是大生意且天然垂直化（CRM、广告、法律、医疗各有成熟体系），中国则是平台侧把大量垂直功能整合进去。由此引出上期节目的悬案——当时正值美国 SaaS 恐慌性抛售、Claude 推出 Cowork 后投资人担心"又一次杀死 SaaS"。张阔的回答核心是一个词：ontology（本体/企业上下文语义）。他的论证：就算请一个大学生进企业，也搞不清楚各条数据到底意味着什么、老板最终经营目标是什么——是为利润率还是市场份额？这直接决定预算、库存、广告的打法完全不同。你没法"扔一个通用 AI 进企业"就自动完成这些。所以演化路径是双向的：简单功能的 SaaS 会被 AI 削弱，但深嵌工作流、握有企业上下文的 SaaS 可以用 AI 升级自己；同时每个技术转折点都会冒出 AI-native 新公司（如法律领域的 Harvey、医疗领域的 OpenEvidence）——"每一个时代都有这个时代的公司"。中美电商形态差异同理：美国 Shopify 独立站 + Amazon FBA 是两端，中国淘宝天猫是"平台获客+集成工具"的中间态，交付的价值项一样，只是形态不同。

### 第六章：Agent = Model × Harness × Context（16:05 - 20:35）
本章是全期的工程框架核心。张阔自述的公式：**Agent = Model × Harness × Context**，并特意强调是乘法不是加法——"哪一项是 0，整个这个公式结果就是 0"。三项含义：Model 是底层模型；Harness 是工程骨架（连接不同工具、管理 memory、做好用户授权，保证系统持续运行）；Context 是业务上下文（阿里的优势项：20 多年积累的商家详情、企业知识库、买卖双方对话、行业趋势数据）。对 AI 产品"第一天全球化"的解释也在这章：模型天生无语言问题，交互以 LUI（语言界面）为主门槛大降，剩下中美差别主要在 harness（接的工具和平台不同）与 context（经营上下文不同）。投入重心的演变：早期 harness 花精力最多；现在 model 上"要花非常多的时间"，且关键发现是 **model 和 harness 必须联合优化**——既不能拿通用 frontier 模型直接用，也不是简单微调（FT），而是基于一定尺寸的模型做后训练（post-training），并在 model、serving（推理服务）、harness 三处同时精细打磨（cache 命中率、准确率、成本），才能拿到最好效果。例证：用千问最新小尺寸模型做 post-train，效果已"非常接近 frontier 的 top 模型"。这就是垂直 Agent 能跑出来的机制解释——竞争力不在模型本身，在三处联调。

### 第七章：107 任务基准——frontier 模型只有 61%（20:35 - 27:05）
全期最有价值的部分。动机直白：模型发布越来越频繁（"我在硅谷待一个礼拜，光个人助理就发了好几个"），每个新模型都说自己全面更好、榜单 99 分，但日常使用"又没有感觉到像说得这么好"。团队因此基于 Alibaba.com 上百万条真实经营数据和 Accio 真实问答，总结出 107 个 task，已开源，希望各模型厂商围绕它做评测。构造：分七大类，每类内部按 L1-L4 分难度——任务越长程、结果越开放，能通过的模型越少。**结果：当前最 frontier 的模型通过率只有 61% 多一点点，"想要达到及格水平现在都有点费劲"**。他特意澄清 61% 的含义：测的是完全无人干预能否做完，不代表工具不能用。任务举例让 benchmark 变得可想象：(a) 报价单筛选——从多个供应商的 quotation 里选出最合适的，要算清从工厂价到含税到手价、比较物流方案，而且里面**故意掺了钓鱼邮件**，测有害信息识别，任一环节算错即失败；(b) 订船——给定交期和起运港，在船务公司网站上真实预订成功才算通过；(c) 纠纷判断——判断买家投诉信息是否完整、结论是赔还是不赔、还是需要更多信息。方法论上还有一个常被忽略的点：benchmark 会"腐化"——模型/Agent 迭代一段时间后老案例可能反而退化，所以每次版本迭代都要重跑 evals。107 只是快照，持续加入更难的任务。这章是对"榜单通胀"的正面回应：通用智能分数与垂直任务完成度"其实没有那么大相关性"。

### 第八章：商业 AGI 的定义与商家真实用法（27:05 - 32:40）
张阔给了一个可证伪的定义：广义 AGI 无定论，但**商业上的 AGI 好定义——给定同样预算、同样供应链，用这个 Agent 经营比一个人做日常操作和判断赚到更多的钱，就是该商业领域的 AGI**。商家侧三大高频用法（来自大量商家访谈；张阔 2011-2016 在淘系做商家平台，现在是换到 AI 产品视角回看）：(1) **多平台利润核算**——国内商家普遍同时在抖音/淘系/京东/拼多多经营，"今天到底哪个平台挣到钱了"需要跨平台看投入、收益、退换货形成完整报表，以前人工来回切换整理 Excel"最终你还不一定算对"，现在随时可出实时结论；(2) **多平台发布商品**——平台规则×受众×媒体形式的叉乘是大工作量，AI 批量处理进草稿箱或授权直接发布；(3) **客服复盘**——以前经营会一条条看谁答对答错，现在 AI 全量分析回答质量，ToB 场景还能对"可能要黄的单子"提前预警。用户的预期也在同步升级：任务难度从 L1（问答）→ L2（交任务）→ L3（复杂任务）→ L4（经营判断）持续上推，"商家每过一段时间就会 push 产品解决更复杂的问题"。

### 第九章：必须留给人的判断（32:40 - 33:45）
短但重要的边界划分。必须人做的：支付、确认采购这批货的按钮——因为要为整个经营结果负责。再往外扩：这个想法靠不靠谱（是不是真问题、目标客户群基数够不够大、愿不愿付足够溢价）、产品的 taste、对此时此刻市场的预测判断、同样预算下"更多广告 vs 更多库存 vs 铺更多渠道保更大毛利"的取舍。AI 可以做全部市场分析、调研、竞对判断，但最终商业判断是人按按钮。这与第一章"可验证性"呼应：经营目标本身不可外包给模型。

### 第十章：成本战——$3.69 vs $9+ 与帕累托路由（33:45 - 37:30）
硬数字：107 个任务全部跑完，Accio Work 成本 3.69 美元，Codex 和 Claude Code 都在 9 美元以上，即三分之一（主持人报数，张阔确认，口径为模型调用成本）。为什么能便宜：其一，帕累托最优路由——L3 以下的简单任务用小尺寸/高性价比模型（含大量中国高性价比模型），多模态/视频需求路由到特定模型，目标是用最低成本拿到同等结果，而不是"模型升级了就都跑最贵的"；其二，集约采购比个人调用便宜；其三，同样的模型，靠 harness 工程和 context 管理拿到更高效率。他观察到商家喊贵的常见原因是"固定选一个最贵的模型解决所有问题"，建议改选 Auto 模式由系统代路由。对比对手的结构性限制：Codex/Claude Cowork 是 Agent 与自家模型绑定，无法做跨厂商路由——这正是美国 OpenRouter、Fireworks 这类模型托管路由生意火起来的原因，也是"模型日益 commodity 化（每隔一段时间就有更好的开源模型出现）"背景下的长期优化空间。访谈当天 GPT-6 Astra 刚发布，主持人问冲击，张阔的回答是全期最"硬"的一句：过两天直接去他们 benchmark 网站看 Astra 评分，"你说它是 AGI，我现在给你打保票，肯定不是 AGI"——3D 模型做得不错、computer use 有突破，都不代表通用商业场景的 agentic 能力强。

### 第十一章：多 Agent 冲突、上云与长程任务（37:30 - 42:50）
三个设计问题。**多 Agent 冲突**：不同平台的 Agent 给商家不同建议很正常，解法不是造一个"元 Agent"统一所有意见（"这不是我们产品设计的初衷"），而是老板自己持有整体经营目标——以毛利为结果还是以规模、速度为结果——以此评判各家建议是否合理；Accio Work 的差异化定位就是站在商家"一本账"的角度跨平台整体优化，而非围绕单一平台优化。**上云 vs 长程是两个概念**：上云只是基础需求（本地 memory 放云端、换机器可续用），"今天你说你没上云，那就是你功能还没做完"，谈不上技术差别。**长程任务分三类范式**：定时任务（每天定时出店铺经营和员工工作报告）、事件驱动任务（基于供应商的新信息推进多方沟通）、季度级经营复盘（这盘生意最终赚没赚到钱）。他明确反对炫技式的长程：与其追求"模型 7×24 跑一个礼拜不挂"，不如定义清楚什么场景需要完成什么目标——"它不挂毫无意义，如果没有解决你的问题的话"。

### 第十二章：CoCreate 大会与两个冠军故事（42:50 - 46:14）
洛杉矶 CoCreate 大会，最让张阔惊讶的是"来的人太多了"：注册到场约 15000 人（自报），注册摊位搞小了，排队排到中午。两个 CoCreate Pitch（类似 Shark Tank 的创业路演）冠军案例：英国冠军是个 15 岁初中生，用 Accio Work 找供应商、发掘产品，做"自动降温毛巾"和宠物自动降温产品系列，年销售额约 100 万英镑；美国冠军 Christian Reed——现场穿着非常工地化，一问是 MIT 毕业的——做酷炫的测量设备，从创意到供应链全基于 Alibaba.com 和 Accio Work，客户包括施耐德电气和 SpaceX，今年生意做到几千万美金以上。收尾叙事：全球中小企业的问题从来不是"AI 取不取代工作"，而是没资源、没经验又想做大；AI + 全球供应链是让小团队把生意做大的放大器。（这章 PR 浓度全片最高，两个案例均为平台自报，读时自行打折。）

## 成色评估
**利益关系：** 有。张阔是 Alibaba.com 总裁，Accio Work 为其亲管产品，全期以该产品为主线展开；主持人与嘉宾无投资关系，属半年内第二次回访。
**数据口径：** 核心数据全部为阿里自报 ⚠️：搜索 +20%/多模态 +130%、107 任务、frontier 通过率 61%、$3.69 vs $9+、15000 人到场、两冠军销售额。其中 107 任务 benchmark 称已开源，是唯一可独立查验的部分。
**PR 指数：** 中高。成本对比、大会盛况、冠军故事明显服务品牌叙事；但 benchmark 构造方法论（L1-L4、防腐化 evals、掺钓鱼邮件的任务设计）、Agent=Model×Harness×Context、帕累托路由经济学有独立于产品宣传的信息价值，主持人也有实质追问（哪些留给人、为什么成本更低、Astra 发布的冲击）。
