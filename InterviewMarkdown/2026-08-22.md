## 分章详解

### 第一章：开场——从模型竞赛到工程竞赛（00:00 - 03:20）
主持人泓君用一组对仗给出全期的时代坐标：如果说 2025 年是 Agent 元年，2026 年行业最显著的变化是话题从"模型的能力"迁移到"Agent 的工程问题"——也就是说，模型层的研究竞赛告一段落，怎么把模型组织成可靠的生产系统成了新战场。她给出的三个证据都很具体：Uber 给员工发放的 Token 额度四个月烧穿了全年 AI 预算后收回；Meta 开始计划限制员工的 Token 消耗量；与此同时 DeepSeek、GLM、Kimi 等中国开源模型的能力逼近第一梯队，硅谷公司开始把它们搭进生产工作流。这就引出全期的核心问题：**"最大化 Token 消耗、无脑用最强模型"还是市场最优解吗？** 嘉宾组合也是围绕这个问题配置的：黄东旭是"真正在玩 Agent 的人"（一线实战视角），张宏江是"大科学家"（产业史与宏观视角）。这一章为后面全部内容立好了靶子。

### 第二章：泡沫之争——基建占 GDP 比例与年降 10 倍的 Token 价格（03:20 - 08:40）
张宏江的论证链条值得完整展开。他去年 12 月就公开说"没有泡沫"，理由有三层：第一，把本轮 AI 基建与互联网早期基建、美国铁路网/公路网建设相比，**绝对投资额虽超过历史，但占 GDP 的比例其实更小**——所以从宏观上谈不上过度投资；第二，Token 消耗量增长极快，说明需求是真实的；第三，也是最硬的一条：**Token 价格过去几年以每年约 10 倍的速度下降**（远超摩尔定律），驱动来自英伟达芯片迭代等硬件进展。他的结论做了精确限定：技术与应用发展没有泡沫，"股票市场是不是有泡沫那是另外回事"。东旭补充了一个漂亮的微观类比：这就像 1950-60 年代看计算机诞生——一个房间大的电子管机器又贵又笨，但个人计算机及后续的所有需求，都是在基建充分之后才诞生的，新需求又刺激新基建。他的判断是"短期可能有小回落，长期仍有大量需求没被看见"。这一章为全期定下"长期主义者"的底色，后面所有降本讨论都建立在这个前提上。

### 第三章：Token Maxing 编年史——一天 $400-500 换千万美金软件（08:40 - 16:00）
这是全期信息密度最高的章节之一。东旭复盘自己的 Token Maxing 史：从 2025 年 11 月开始，他用 Opus 从 0 到 1 构建他"能想到的最复杂的软件"——云原生分布式数据库 **db9**（他做了多年 TiDB，分布式数据库是公认最复杂的系统软件之一）。他解释为什么当时必须无脑用最强模型：在最复杂任务上，人无法精确评估第一强和第二强模型的差距，只能看 benchmark，而 benchmark 可以刷榜；当任务确定很难时，唯一理性策略就是永远选最强的。当时 Opus 和 GPT-5.1 对第二档 coding Agent 是"断崖式领先"。**成本端：一天 $400-500，而且这还是在付了 Claude Code Pro Max $200 订阅、用完限额后额外购买超额用量的基础上。** 收益端他给了可验证的锚点：这个软件 PingCAP 的销售团队已期待多年，做出来后一年可新增约 1000 万美金直接收入（嘉宾自报 ⚠️），而他"一个人、三个月"就做完了。他由此提出全期最核心的概念修正：**Token Maxing 是一个结果、一个滞后指标**——经过思考的疯狂使用产出好结果；但大公司把它误解成了 KPI。Jensen 在 GTC 要求工程师烧 Token、Meta 搞 Token 排行榜之后，必然出现"刷榜式无效调用"（他讽刺说让 Agent 算 100 万遍 1+1 也能刷上榜首）。这一章同时解释了 Token Maxing 的合理性与它被异化的过程，为后面"范式转向"埋下伏笔。

### 第四章：OpenClaw 的兴衰——捅破一张纸的普罗米修斯（16:00 - 23:00）
OpenClaw（社区昵称"小龙虾"）为什么火？东旭从开源爱好者视角给了三层解释：其一，开源天生更具传播力，且它的理念是 **local-first**（隐私数据全部本地配置），这是硬核极客才会做的技术选择，在极客圈子的传播"有点像当年 Linux"；其二，时间点上，用户已用 Chatbot 三年多（"只能交流，不能做事"），Claude Code 让人看到 Agent 能做事，OpenClaw 把 Agentic loop + 工具调用这套理念做成了普通人可用的产品形态；其三，2 月春节前后 Claude 模型升级带来的"天壤之别"的智能跃迁是临界点。张宏江的总结更宏观：Peter Steinberger（一个架构师而非科学家）一个礼拜 hack 出 OpenClaw，加上东旭三个月做出分布式数据库，共同标志**大模型能力跨过了"真的可落地"的坎——行业从研究进入工程、从模型进入 Agent**，而且你不再需要深懂模型机理就能做系统。媒体披露 Peter 当时 30 天 API 账单高达 130 万美金（转述 ⚠️），侧面说明其使用强度。但东旭对 OpenClaw 的现状判得很冷：质量没有精雕细琢、配置难度和系统稳定性随用户规模放大而成问题——"软件复杂性超过临界点后，非常 senior 的研发团队还是非常必要的"；它"起得太早"，更像实验性项目，Peter 去 OpenAI 后公司精力转向 Codex，项目靠基金会运转。他的终局判断：OpenClaw 扮演了**普罗米修斯**的角色——把产品形态和能力让世人知晓后，历史使命就完成了，天花板也就这样了。

### 第五章：Hermes——用"总结成 skill"绕开记忆难题（23:00 - 27:00）
OpenClaw 最大的用户痛点是记忆：不做记忆储存时靠对话压缩（Compaction），不停回滚、老忘事、还特别费 Token。东旭很快从 OpenClaw 切换到 Hermes（Nous Research 出品）并成为重度用户。他的分析很锋利：**Hermes 的亮点不是记忆模块设计得多出彩，而是巧妙绕开了记忆问题**——它的 Agent 框架有很强的倾向去不停总结成功经验、沉淀成 skill。OpenClaw 的 Agent Loop 缺少反思过程（除非你主动要求它整理 skill），Hermes 则内置了这类机制，用一段时间就"长出"很多你自己实践过的最佳实践。东旭特别戳穿了营销话术："世界上第一个自我改进的 Agent"这些词是 marketing，本质是**模型能力 + 工程化手段总结经验**，跟模型本身的能力无关——"有点像一个更好的学习习惯"。工程质量上两者也形成对照：OpenClaw 是"大集市"（Peter 谁的 PR 都合，"代码也不看了，Agent 说没问题就行"），Hermes 是团队精心打磨的架构，onboarding 和稳定性都更好。商业模式上，Hermes 类入口的生意本质还是 Token 经济学：帮模型厂商带消耗、拿渠道折扣。这一章与下一章一起，构成"Agent 入口价值"的论证。

### 第六章：Agent 成为唯一入口——终极推荐算法在本地（27:00 - 30:20）
东旭自述"智能原教旨主义者"式的使用方式：OpenClaw 出来后他再没打开过 Gmail——每天让 Agent 汇报新邮件、判断哪些需要回、广告邮件直接删。他信任模型的判断（Opus 4.8 认为重要的邮件，大概率他也认为重要），模型不确定时会明说并请他做最终裁决。信息获取同理：邮件订阅、Hacker News 都先让 Agent 总结，感兴趣再点原文。他由此推出一个颠覆性判断：个人 Agent 拥有你所有的数字足迹（记忆、浏览记录、偏好），并通过"养龙虾"式的持续迭代越来越懂你——**"真正终极的推荐算法，就是在你本地、在你旁边坐着一个观察你生活的智能"**，传统媒体基于大众趋势训练的推荐系统会被釜底抽薪。主持人泓君提供了重要的平衡视角：她试过让 OpenClaw 精选新闻但最终放弃，因为"给我的东西太浅"，她宁愿读更少但更深的一手文章；涉及决策的邮件（比如约录制时间）也绝不交给 Agent，只把它当过滤器。这一章的分歧（全自动派 vs 深度阅读派）恰好展示了 Agent 入口革命的边界在哪里。

### 第七章：Slock——Agent 群聊与"一天 10 亿 Token"（30:20 - 35:30）
Slock（已改名 Raft）由 Kimi CLI 负责人钱宇超创立，东旭是第一个天使投资人和早期用户。产品概念一句话：**Slack for Agents**——一个聊天室，里面聊天的都是 Agent；它们互相不共享运行上下文，唯一共享的是频道里的信息（与行为艺术色彩浓厚的 MoltBook 异曲同工，但 Slock 保留了其中"有用"的部分）。核心用法是复杂软件项目的代码审查：10 个 Agent（混用 Claude Code、Codex 等顶级模型）给同一段提交挑刺——"我看出来 3 个问题""前 3 个我认同，但我又发现一个新的""哥们你说得有道理，我再继续看"——持续迭代。效果：挑出的问题深度和改进质量"完全不同于"单模型 one-shot 审查；代价：Token 消耗约 10 倍。**东旭的峰值用量：一天约 10 亿 Token，对应账单三四百美金。** 他的方法论是：任何关键决策前强制 Agent 群多轮讨论，终止条件是"谁都挑不出更多毛病"。他借用 Slock 团队发明的词"Agent 动力学"来解释为什么群聊有效：让 Agent 长时间持续运行很难（长程任务会顾此失彼），而今天所有 Harness 工程、Loop Engineering 本质都在优化同一件事——让 Agent 在特定任务上持续干活。群聊的互相刺激、Loop Engineer 的"强行抽自己一鞭子再 review"、Harness 的复杂工作流，殊途同归。他给的类比极其亲民：小时候做完作业，父母总说"再重新算一遍"——第二遍确实能发现第一遍的马虎。这一章是理解后续"蜂群"讨论的实证基础。

### 第八章：三大转折——Fable 5 的智商碾压与本地开源的宽带时刻（35:30 - 43:20）
东旭今年三四月的认知（Agent 群协同是终局）在三个月内被三个模型事件击穿：**GPT-5.5、DeepSeek V4、Fable 5**。第一击是 Fable 5 的绝对智商：多 Agent 讨论的前提是"不相信任何一个 Agent 的 one-shot 成功率"，但 Fable 5 强到"那边讨论得不想再讨论了还是做不出来"的问题，它**在没有前情上下文的情况下一次搞定**——"我前面烧了 10 亿 Token，在 Fable 5 这边非常精准地一次搞定了"，这是绝对的智商碾压。第二击是 DeepSeek V4：他说自己以前"不相信开源模型"能做复杂软件开发，但 V4 的质量已经"非常实用"，随后的 GLM-5.2（智谱）又把认知往前推一大步。这开启了他的新架构：**顶级闭源模型 + 便宜开源模型协同**，他类比为"一个企业真正出现管理学了"——不可能全公司都是资深专家，还需要大量能写 code 的工程师。第三击是成本侧的落地：他在 Mac Studio 本地跑 DeepSeek V4 Flash，约 30 Token/s（与 API 速度相当），**满载一天电费约 $1、一月二三十美金**（自报实测 ⚠️）。这解锁了两类此前"不敢用付费模型做"的事：重复性日常工作（整理自己的文章记忆和数字足迹，即"自我蒸馏"），以及批量论文总结（CVPR/NeurIPS 一期几百篇，用 API 要几百刀，本地随便跑）。他的"宽带比喻"是这一章的诗眼：1997 年拨号上网按分钟花钱，大家省着用；免费宽带和大容量套餐才催生出抖音、视频会议——**智能的免费/近免费与低价之间有天壤之别**。最终账单从一天 $400-500 降到一月 $200-300（约等于一个最高版 Claude + 一个最高版 Codex 的订阅费）；主力模型从 Opus 迁移到 GPT-5.5/5.6 + Codex，最复杂任务（数据库疑难杂症、同时改七八个模块、提交五六千行代码）留给 Fable 5。他的标准操作：Slock 里的 Agent 解不了的问题，让它们写报告解释为什么解不了，把报告直接发给 Fable 5。人的角色收敛为：**定目标、验收、把控架构；中间过程全部交给 Agent 协同——"Agent 的管理学"**。

### 第九章：Agent 为什么烧 Token——Agentic Loop 机制与杰文斯悖论（43:20 - 48:20）
面对主持人"Claude 和 OpenAI 的 API 消耗与 ARR 还会增长吗"的问题，东旭先拆解 Agent 烧 Token 的机制（这是全期对小白最友好的一段技术解释）：每个 Agent 内部都有一台"发动机"叫 **Agentic Loop**——本质还是对话机，但把对话变成了循环，每个循环都调用大模型；它有两个烧钱特性：一是循环中调用外部工具，工具的输入输出都变成对话上下文；二是长程任务下循环可能跑几百步，每步又有嵌套的工具调用。这个范式使 Token 消耗比 Chatbot 时代"涨了 100 倍都不止"。剔除人为浪费（刷榜）后，结构性消耗仍在放大：单 Agent 之上会长出多 Agent 协同网络，网络之上又会有更抽象的 loop——分层结构已出现。张宏江此时点出经济学名词**杰文斯悖论（Jevons Paradox）**：技术越成熟、价格越低，消耗量反而越大，市场总量变大——完美解释了"单位成本下降"与"总消耗暴涨"并存的现状。东旭补了一个软件工程史类比：家酿俱乐部时代大家分享 200 行的 BASIC 程序，今天的 Photoshop 是数千万行代码——今天的 Agent 应用还"太简单"，未来 Agent-to-Agent 网络和 Agent Harness 软件工程出现时，Token 消耗会再上一个台阶。这一章回答了"降本会不会利空模型厂"的疑问：单点优化是局部问题，总量增长是结构性趋势。

### 第十章：蜂群 vs 超级模型——一个经济学判断（48:20 - 53:00）
主持人抛出尖锐问题：Fable 5 一次搞定 Agent 群讨论不出的问题，是否证明超级模型能碾压蜂群？张宏江的回答是全期最精彩的逻辑反转之一：**"没有任何东西可以阻拦蜂群里的每一个 Agent 也利用这种智能"**——模型智能往上 scale，蜂群智能同步往上走。而且把 Fable 5 直接拉进讨论，"它可能第一句话，这些人马上就开窍了"——涌现出 insight 的概率更高。他引用近期一篇清华大学的论文：多 Agent 群体展现的智能**大于**个体能力的简单加总（三个臭皮匠的涌现效应）。东旭从系统可靠性角度补刀：他不相信绝对中心（"太危险"），真正有韧性的系统一定是"大规模基于简单规则连接的分布式系统"。张宏江用云计算史佐证：AWS 设计云时每个节点并不是企业级服务器，但整体可靠性通过分布式实现，总成本反而低于全买最贵节点——"最终你发现它其实不是一个技术的判断，最后是个经济学的判断"。（这也是对某些沿用企业级思路建云的厂商成本居高不下的解释。）这一章把"模型碾压 Agent 创业公司"的焦虑转化为一个架构经济学问题，直接引出下一章的投资判断。
